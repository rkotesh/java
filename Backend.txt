JUnit5 :
JUnit 5 is the modern testing framework for the Java Virtual Machine (JVM), featuring a completely modular architecture. Unlike previous monolithic versions, it is split into three major components to separate test discovery and execution from the actual programming models

• JUnit Platform: The underlying foundation that launches testing frameworks on the JVM. It defines the Test Engine API and integrates with build tools (like Maven or Gradle) and IDEs to discover and execute tests.
• JUnit Jupiter: The modern programming and extension model used to write tests in JUnit 5. It contains all the new annotations (like @Test, @BeforeEach, @ParameterizedTest), assertions, and the dedicated engine to run them.
• JUnit Vintage: The backward-compatibility engine. It allows legacy tests written in JUnit 3 and JUnit 4 to run seamlessly on the new JUnit Platform.

Logging : is the process of recording info about an application, execution, activities, warnings and errors.
it helps developers understanding what is happening inside an application without stopping its execution or debugger.

Why do we use logging 
1. debugging -> identify problems in the application
2. monitoring -> track application behaviour 

Types log levels :
1. TRACE : verify detailed diagnostic info, useful for tracing program execution
ex:- log.trace("Entering findStudent());

2. DEBUG : detailed info useful during development and debugging
ex: log.debug("Searching for student id:()", id);

3. INFO : normal application events and successful operations
ex: log.info("Student registered successfully");

4. WARN : unexpected situations that need attention but do not necessarily skip execution
ex: log.warn("student record is missing in optional field");

5. ERROR : failures that prevent an operation for completing successfully
ex: log.error("Failed to save student");



Code		Purpose

Logger		provides logging methods

log.info	records informational messages
log.warn	records warning messages
log.error	records error messages
{}		placeholder for a value

Exceptional Handling :
is an event that occurs during program execution and disrupts the normal flow of instructions.

why do we need exceptional handling -> it provides meaningful error message separate business logic from error handling maintains application stability return appropriate http status code from rest api.

Types of exception :
1. checked exception -> exceptions are checked by the compiler, a method must handle them with try, catch or declare them with throws.

2. unchecked exception -> is a subclass of runtime exception the compiler does not require them to be catch or declare.
